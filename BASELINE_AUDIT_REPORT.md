## 1. Root Cause of the Model A 11.16% Discrepancy

### The Inconsistency
Historically, `ml/artifacts/metrics.json` recorded the production baseline as:
- **Accuracy**: `0.9970` (99.70%)
- **Macro-F1**: `0.9956`

However, when `model/weights/best_model.pth` is evaluated on the 4,025 held-out PlantVillage test set images (`data/split/test`), it scores:
- **Accuracy**: `0.1116` (11.16%, 449 / 4,025 correct)
- **Macro-F1**: `0.0451`

### Forensic Investigation Findings
An exhaustive audit of the codebase, git history, and checkpoint layer weights revealed the precise root cause:

1. **Commit Artifact Disconnection (`89144a2`)**:
   - In commit `89144a26f73c497db3e026fc270bf34ba161d269` ("AgriSmart AI Full Platform Release"), the metrics file `ml/artifacts/metrics.json` contained results from a legitimate 15-epoch training run recorded in `ml/artifacts/training_history.json` (where epoch 13 achieved `val_f1 = 0.9967`).
   - However, the binary checkpoint file committed as `model/weights/best_model.pth` (Git blob `3179b0d667ba09eb36ef2bb745daa76244632567`) was **not** produced by that 15-epoch run.
   - Instead, `best_model.pth` was overwritten immediately prior to the release commit by executing `model/calibrate_model.py`.

2. **Mechanism in `model/calibrate_model.py`**:
   Inspection of `model/calibrate_model.py` reveals the following weight generation routine:
   ```python
   # Map sample images if available to their exact ground truth classes
   sample_mapping = {
       "apple_scab.jpg": 0,           # Apple___Apple_scab
       "corn_common_rust.jpg": 7,     # Corn_(maize)___Common_rust_
       "grape_black_rot.jpg": 10,     # Grape___Black_rot
       "potato_early_blight.jpg": 18, # Potato___Early_blight
       "tomato_late_blight.jpg": 25, # Tomato___Late_blight
   }
   
   # For all 33 classes:
   # If in sample_mapping, use real photo from frontend/public/samples/
   # If NOT in sample_mapping, generate a synthetic PIL oval drawing (create_prototype_image)
   weight_tensor = prototype_features * 16.0
   bias_tensor = torch.zeros(num_classes)
   ```

3. **Mathematical Proof of Weight Collapse in `best_model.pth`**:
   - **Tied Row Norms**: All 33 rows of `classifier.1.weight` have an exact L2 norm of `16.0000` ($16.0 \times \text{unit prototype}$).
   - **Zero Biases**: All 33 bias entries in `classifier.1.bias` are exactly `0.0000`.
   - **Identical Rows**: For classes where `create_prototype_image` used identical RGB color tuples (e.g., `Apple___healthy`, `Grape___healthy`, `Tomato___healthy`), the cosine similarity between their classifier weight vectors is **1.000000**.
   - **Extreme Prediction Bias**: Real leaf photographs from PlantVillage or field cameras do not resemble synthetic PIL drawings; their feature representations are overwhelmingly closer to the **5 real photo prototypes** (`Apple_scab`, `Corn_rust`, `Grape_black_rot`, `Potato_early_blight`, `Tomato_late_blight`).
   - **Empirical Prediction Distribution**: Across all 4,025 held-out PlantVillage test images:
     - `Apple___Apple_scab`: 2,051 predictions (51.0%)
     - `Grape___Black_rot`: 650 predictions (16.1%)
     - `Potato___Early_blight`: 571 predictions (14.2%)
     - `Tomato___Late_blight`: 501 predictions (12.4%)
     - `Corn_(maize)___Common_rust_`: 241 predictions (6.0%)
     - *All other 28 classes combined*: 11 predictions (0.27%)
     - **Total onto the 5 classes**: **4,014 / 4,025 (99.73%)**.

4. **Why Demo Photos Passed 100%**:
   Because `tests/test_5_photos.py` and the frontend UI sample buttons used the exact 5 sample images mapped in `calibrate_model.py`, `best_model.pth` scored 5/5 (100.0%) on those samples. However, on any general 33-class dataset, the model collapses into predicting almost exclusively those 5 classes.
   Its accuracy on PlantVillage (11.16%) is simply the proportion of true samples from those 5 classes that happen to be in the test set.
